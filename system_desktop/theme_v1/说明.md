# 设备桌面：暖夜守护主题

2026-10-21 已完成第二版修复并安装到用户的 ALPHA i.MX6ULL eMMC 开发板、1024×600 RGB 屏。整板重启后的实机画面见 `evidence/desktop_v2_after_reboot.png`。

## 使用

- 15个原厂应用图标重新绘制，与原“设备守护”人物图标统一为酒红、象牙白、金色、白狐耳与缎带风格。设备守护原人物图标保留。
- 系统壁纸为同风格暖夜书房白狐守护者插画。16个应用统一排为4×4网格，时钟、记事本、仪表盘、文件移到第四行，底栏和第二页已移除。
- 屏幕右侧固定三键：返回、主页、任务。应用内容缩放至左侧952像素，触摸坐标随Qt变换同步映射。
- “返回”：先关闭任务面板、收起输入法，再返回应用内上一层；根页面返回桌面。已适配文件目录、相册、记事本和设置页；设备守护从参数/记录/说明返回监测页。
- “主页”：回到系统桌面并保留应用进程、当前页面。设备守护继续在后台采集；重新打开时恢复同一界面和采集服务。
- “任务”：列出当前应用、后台驻留应用和最近使用的应用。后台驻留项恢复原进程；最近使用项重新打开。点击当前应用只关闭任务面板。在桌面的任务页点击“结束”才会真正关闭应用并释放内存，记事本先调用原保存逻辑，设备守护正常停止采集。
- 设备守护左下角电源键仍用于完全退出。后台留存指同一次开机内的驻留，不是断电后继续运行进程。
- 可用内存不足96MiB时，系统提示先结束不用的应用，不自动丢弃已有页面；仍可恢复已驻留应用。

## 开机与后台修复

首版只验证了桌面进程重启，漏掉了整板开机环境。现场发现开机时 `HOME=/`，手动测试时为 `/home/root`；两个位置存在不同的Qt磁盘缓存。开机加载了旧的主QML缓存，因此出现侧栏消失和空白第二页。

现在桌面入口固定使用独立的 `XDG_CACHE_HOME=/opt/device_guard/system_theme/cache/v2`，原厂应用继承同一环境，避开两个旧缓存目录。后台名单也从原厂的音乐/视频扩展到主页16个应用。普通应用隐藏窗口而不退出；设备守护通过独立命令通道切换界面与桌面，后台采集服务继续运行。

整板执行 `sync; /sbin/reboot` 后，内核启动编号由 `57a6f4fd-6e79-4cd8-b71b-3e840f7e1a14` 变为 `88919a0f-f963-4fb5-a91a-36cecc937998`。开机环境为 `HOME=/`，16图标网格和右侧栏的帧缓冲区域与重启前逐字节一致；左右滑动后也一致。验证的是实际整板软件重启，未声称做过拔电测试。

文件管理器、记事本和设备守护同时驻留通过：文件目录在切换其他应用后逐字节保持，记事本恢复同一个编辑页，设备守护后台采集计数持续增长、恢复原进程及参数页。重启后再测LED回主页驻留、任务页结束及列表自动刷新均通过。

## 性能与实测

移除原桌面的模糊面板、遮罩和空分页，使用普通Qt Quick绘制、按显示尺寸准备图标及壁纸。任务服务采用原生C程序和长连接等待，空闲时不高频轮询。没有提高CPU频率或更换内核。

以下为首版主题在同次开机、相同帧缓冲判定方法下的历史测试，改造前后各测2次；第二版增加了真正的多应用驻留，实际总内存随打开应用数变化：

| 指标 | 改造前 | 改造后 |
| --- | --- | --- |
| 桌面首屏 | 1.889 / 1.855秒 | 1.412 / 1.410秒 |
| 桌面进程RSS | 43452 / 43752 KiB | 33696 / 33776 KiB |

平均首屏时间减少约24.6%，桌面进程RSS减少约22.6%。新增任务服务单独实测RSS为372 KiB。这里衡量的是桌面进程启动和内存，不代表所有应用帧率均提升相同比例，也不是断电冷启动测量。

真实触摸事件验收通过：LED主页/任务/返回；文件目录返回父目录；相册预览返回列表；空白便笺返回列表；视频后台进程恢复；设置根页面返回桌面；设备守护参数页返回监测、真实六轴在线和跨应用切换。没有摄像头，未声称完成相机拍摄验证。

第二版验证记录：`evidence/v2_full_reboot.json`、`v2_guard_background.json`、`v2_ordinary_background.json`、`v2_post_boot_background.json`。监测配置保持原字节内容，没有清空已有事件和便笺。第二版21项回退文件及其原始备份已只读核验。

## 文件与复现

- `art/`：高分辨率图标和壁纸原图。使用内置 `image_gen` 生成，完整提示词及来源记录在 `art/generation.json`。
- `runtime_src/qml/`：新桌面、公共应用外壳、三键导航、HTTP调用脚本。
- `runtime_src/navd.c`：只监听127.0.0.1:18767的任务服务，只接受桌面配置中的已知应用；通过原厂服务启动应用。
- `runtime_src/desktop_entry.c`：原生桌面入口，启动任务服务后进入原厂桌面核心。
- `prepare_assets.cjs`：Sharp将图片准备为实际显示尺寸，并生成字体标题和导航小图。
- `prepare_apps.py`：从保存的原厂程序准备QRC桥接，保留原生驱动逻辑、资源表和可执行文件长度；`qml_original/`保留提取的原始QML。
- `original_apps/`、`original_systemui`、`original_guard/`：本次改动前用于复现的版本。
- `payload/`、`theme.tar.gz`：板端文件与部署包。此包针对本板已经核对的原厂版本及此前单页桌面，不是任意开发板的通用刷机包。
- `install_theme.py`：先校验版本、备份文件与对应QML缓存，再安装；启动失败时自动恢复。
- `restore_theme.py`：检查当前文件仍匹配本次安装结果，再恢复备份，避免覆盖后续修改。
- `upgrade_v2.py`、`upgrade_v2.tar.gz`：针对已经安装首版的本板，备份后应用后台、缓存和16图标布局修复。
- `restore_v2.py`：将第二版回退至首版，`--check`只读校验备份。`verify_v2.py`保存真实触摸、页面驻留与整板重启验收方法。
- `src/device_guard_view`：以原厂最小Qt程序为宿主的独立界面程序，原始版本与入口桥接重建过程保存在此目录，见工程 `NOTICE.md`。

在已有Sharp的Node环境运行 `node prepare_assets.cjs`，再运行 `python prepare_apps.py`。在已有ARM交叉GCC的WSL中运行 `sh build_native.sh` 和工程的 `sh tools/build_launcher.sh`，最后运行 `python pack_theme.py`、`python pack_upgrade_v2.py`。`payload/guard/Main.qml`为公共导航外壳，`GuardContent.qml`为已有HUD的后台适配版本。

完整工程部署包 `../../build/device_guard.tar.gz` 已同步新版监测UI。新增“任务”功能依赖本系统主题服务，因此复现时须同时保留或安装本主题。完整交付ZIP同时包含本目录。

## 板端位置与恢复

运行目录 `/opt/device_guard/system_theme`。系统入口 `/opt/ui/systemui`；保留的原厂核心 `/opt/ui/systemui.core`；15个应用仍位于 `/opt/ui/src/apps/`。

第二版安装前的有效备份：`/opt/device_guard/system_theme/backup_v2_20261021_02/`；首版主题安装前的备份仍位于 `/opt/device_guard/system_theme/backup_20261020_02/`。恢复时先在桌面的任务页结束所有后台应用，再运行：

```sh
python3 /opt/device_guard/system_theme/restore_v2.py --check
python3 /opt/device_guard/system_theme/restore_v2.py
```

上述命令回到首版主题及其原后台策略。如还需恢复主题安装前的原厂桌面，再运行 `python3 /opt/device_guard/system_theme/restore_theme.py`。若检查发现后续改动，工具会停止并指出文件，不会强行覆盖。
